# capture —— 抓包与取证材料目录

本目录存放**逆向阶段的抓包、截图、日志**，以及运行期的采样记录。
内容含会话凭据或个人数据，**已被 `.gitignore` 排除，不要提交**。

| 文件/目录 | 内容 | 是否提交 |
|---|---|---|
| `client_recon.md` | 登录流程的逆向记录（回调契约、Cookie 名） | ❌ 记录了完整逆向过程 |
| `tournament_info.md` | 赛事接口字段的实地记录 | ❌ 同上 |
| `samples.jsonl` | 轮询采样历史 | ❌ 运行时数据 |
| `state.json` | 轮询器状态快照 | ❌ 运行时数据 |
| `poll.log` `watchdog.log` | 运行日志 | ❌ 含账号、邮箱、IP |
| `*.png` | 设备截图 | ❌ 可能含账号信息 |
| `*.bundle.js` | Frida hook 构建产物（源码在 `scripts/capture/`） | ❌ 构建产物 |

## 为什么整个目录都不提交

两个原因：

1. **凭据**：日志里出现账号昵称、邮箱与服务器地址；截图可能含账号信息。
2. **合规**：`client_recon.md` 完整记录了登录流程的逆向结论。它与源码里
   的签名实现性质相近——公开源码已经足够说明问题，无需再附一份过程记录。

这些材料对**本地复现**仍然有价值，因此保留在磁盘上（只是不提交）。
若要归档，建议移到仓库外，例如 `D:\sve-forensics\`。

## 运行期需要本目录存在

`state.json` / `samples.jsonl` / `poll.log` 会写在这里，所以目录本身需要保留。
本 README 就是为了让空目录能随仓库存在。
