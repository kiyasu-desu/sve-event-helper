# SVE 赛事助手（客户端）

通用化的赛事工具：**多账号登录 → 按地区浏览赛事 → 订阅后自动报名**。
本地 Web 界面，可后续迁到服务器。

## 启动

```powershell
# 方式一：批处理
.\app\client\run.bat

# 方式二：直接跑（可改端口）
$env:SVE_CLIENT_PORT = "8801"
& .\vendor\venv-client\Scripts\python.exe -u app\client\server.py
```

然后浏览器打开 **http://127.0.0.1:8801**。已有旧数据须先按 [M01 迁移说明](../../deploy/M01-account-identity.md) 离线预览与迁移；服务不自动改写旧数据。

> 使用独立环境 `vendor/venv-client`（Python 3.11）。项目主环境是 3.14，
> 很多 GUI/浏览器相关库对它支持还不完整。

## 目录结构

```
app/client/
├─ core/                     ← 纯逻辑，无 UI 依赖，可单独复用/测试
│  ├─ sveapi.py              API 客户端：签名、list/detail/action/login、多账号
│  ├─ weblogin.py            登录窗口 + 读取 Cookie + 换会话
│  └─ scheduler.py           报名调度：窗口归一化 + 两段复核状态机
├─ server.py                 Flask 后端（薄 HTTP 层 + 状态编排）
├─ ui/index.html             单页界面
├─ data/                     账号、订阅、日志（本地私有）
└─ run.bat
```

## 登录是怎么做的（重要）

**不是**代替你输入密码，而是：

```
1) 用 Edge 打开网易官方登录页（伪装移动端 UA，否则该页不渲染）
2) 你在窗口里完成登录 —— 标准网页登录，与在官方 APP 里登录等效
3) 工具从浏览器读取网易账号 Cookie（CDP，只读）
4) 用这些 Cookie 调 POST /urs/login → 得到 SVE 的 sessionid
5) 保存 sessionid，之后所有请求靠它认证
```

依据：`capture/client_recon.md` 第十二节（2026-10-10 实测成功）。

**为什么不用"登录页回调"**：官方 APP 让登录页把结果 POST 到它自己的 API；
我们试过把回调指向本地服务，但该页在回调后会等一个带跳转目标的响应，
容易卡在"正在跳转"。改为"读 Cookie 换会话"后完全绕开回调。

## 关键技术事实（都已实测）

| 事实 | 说明 |
|---|---|
| 签名 | `SHA256(按 key 排序的 "k=v" 拼接)`，其中插入一项 `<udid>=<appKey>` |
| 签名**依赖** udid | udid 作为键名进入签名，须与 `deviceid` 头一致（不要求是真实设备 ID）。与设备无关的是下一行的 sessionid |
| **list 的签名要带 query 参数** | detail 用空 body 即可；list 不带 query 会 403 |
| `/urs/login` 只需 Cookie | 不校验 `sign`、不校验 `sessionid` |
| sessionid 与 deviceid 无关 | 同一 sessionid 配任意 deviceid 都能取到正确账号 |
| 三个 action | `signup` 报名 / `cancel` 取消 / `book` 预约 |
| 列表不给准确名额 | `player_num` 为 None，必须再调 detail |
| **「我的赛事」用 `mine=1`** | 这是**服务端筛选**：`GET /urs/tournament/list?mine=1` 一次返回跨地区的全部参与记录（含已结束/已取消）。**不带 `area` 时返回跨地区数据**，无需逐地区扫描 |
| 「我的赛事」的干扰参数 | `user_status` / `only_mine` / `is_mine` / `user_only` / `uid` / `status` 等**服务端全部忽略**（返回结果与不筛选一致），别被误导 |
| 两种报名形态 | 每日时段型（目前只见于大奖赛）／单次开放时刻型（其余全部） |
| 预约不会自动报名 | 到点也不会提醒；关键仍是开放时刻自动 `signup` |

## 自动报名的安全设计

调度器沿用主项目已验证的状态机：

```
到点前低频轮询 → 临近开放切高频 → 开放后提交报名
   → 立即复核（+2s，判断"打中没有"）
   → 静默等待 60s
   → 二次确认（判断"座位是否坐稳"）
   → 两段都过才判定成功
```

- 只对**订阅的**赛事动作，且要求服务端状态为「可报名」；
- 复核区分**网络错误**（窗口内重试）与**状态错误**（立即判定失败）；
- 成功/失败/未稳定 都会记入日志与界面。

## 两种执行位置：本机 / 服务器

自动报名可以在**本机**跑，也可以交给**服务器上的代理**跑。同一时间只能有一处，
否则会对同一账号重复提交。

```
本机执行（默认）
  客户端 :8801  ── 自己建调度器 ── 自动报名

服务器执行（推荐 24/7）
  客户端 :8801  ── ssh -L 隧道 ──► 服务器 sve-agent :8901 ── 自动报名
      · 订阅动作转发给代理，本机**不建**调度器（本机保留缓存但不执行）
      · 订阅页展示的是服务器的订阅与调度日志
      · 明确登录成功后提交单个会话，服务器再次校验 UID；不推送离线整表
```

启用方式：客户端页面右侧「自动报名执行位置」→ 填主机/用户/私钥 → 启用远端执行
→ 只读比较账号；新增/更新会话请在新版客户端明确重新登录。配置存在 `data/remote.json`，客户端重启会自动恢复隧道，
**不会**悄悄退回本地执行。

### 唯一执行点保证

订阅以 `(账号, 赛事)` 为键，远端模式下本机不创建任何调度器；
服务器明确删除账号时停止该账号的订阅；远端界面的明确删除使用服务器账号 ID、版本和幂等操作标识；不会因缓存缺席而删除。
远端模式启动时保留本机缓存的订阅，但不恢复本地调度器，也不进行孤儿清理。
仍有本地订阅在运行时拒绝启用远端模式，须先明确停止本地执行。

### M01 UID 账号协议（保留 M00 整表保护）

旧 `/api/accounts/sync` 仅作只读兼容：不新增、不更新会话、不删除、不修改服务器 active。
按钮已改为「比较两端账号」，仅显示数量与差异。旧界面可能仍显示推送成功，但响应的
`readonly: true`、`pushed: []` 表示未写入；需更新电脑客户端后才能提交新会话。

新版通过摘要获取会话前置版本，再提交本次明确登录的单个账号；服务器重新校验官方 UID。
旧缓存不能自动重建已删除账号；连接旧服务器不会回退到不安全的整表协议。
同名异 UID 可以共存；同 UID 改名重新登录仍更新同一个账号，订阅与记录引用不变。名称有歧义的旧请求会拒绝，未知 ID 不回退 active。
手机 App 原 `/api/login/cookie` 请求和响应继续兼容，无需重新安装 APK。

M00 的数据保护继续保留；当前 schema、UID 兼容范围及事务迁移/回退见 [M01 说明](../../deploy/M01-account-identity.md)。

## 通知设置（界面可改）

通知凭据可以在界面里设置，不必再手改 JSON：

```
通知设置 → 编辑通知渠道   → 填 PushPlus token / SMTP 信息 → 保存
                          → 「发送测试通知」验证是否真的可用
```

**存储位置**：`<DATA_DIR>/notify.json`（默认 `app/client/data/`，权限 600）。
放在数据目录而不是仓库里的 `config/`，是为了让"仓库中永不含凭据"成为
**结构性保证**，而不是靠 `.gitignore` 的自觉。配合 `SVE_DATA_DIR`
还能把整个数据目录搬到仓库外。

**三层优先级**（高 → 低）：

```
环境变量  >  <DATA_DIR>/notify.json（界面写入）  >  config/settings.json（旧位置）
```

保留最底层是为了向后兼容——老部署的 `settings.json` 依然直接可用。

**几条刻意的设计**：

| 设计 | 原因 |
|---|---|
| 设置接口只返回配置标记、来源、可编辑状态及必要开关 | 不返回密钥摘要、私人路径、服务器地址或邮箱配置原值 |
| 文本、密钥与端口输入框**留空 = 不修改** | 服务端合并已有配置后校验；重新进入或成功保存后输入为空 |
| 环境变量提供的字段**界面只读** | 不然会出现"改了不生效"的困惑 |
| 「发送测试通知」会真的发消息 | 避免"填了就算配好"；按钮做了防连点 |
| `notify.json` 里**不写凭据**（若留空） | 保持最小写入 |

**支持的环境变量**（优先级最高，便于轮换密钥）：

```
SVE_PUSHPLUS_TOKEN      SVE_SMTP_HOST      SVE_SMTP_USER
SVE_PUSHPLUS_ENABLED    SVE_SMTP_PORT      SVE_SMTP_AUTHCODE
SVE_EMAIL_ENABLED       SVE_SMTP_SSL       SVE_SMTP_FROM  SVE_NOTIFY_TO
```

> systemd 的 `Environment=` 会出现在 `systemctl show` 输出里，
> 凭据建议放 `EnvironmentFile=`（其内容不会被 show 出来）。

**注意**：通知是由**执行自动报名的那一方**发出的。远端模式下那是服务器上的
代理，所以改配置时要打开**服务器的 UI**（经隧道 `http://127.0.0.1:8901/`），
而不是本机客户端——本机改的是本机那份，对服务器无效。

## 已知限制

- **登录窗口需要 Edge**，且该页偶发空白（约 1/4 概率，与登录逻辑无关，重开一次即可）；
  根除需换自带 Chromium 的外壳，但本机 Electron 因环境限制无法创建渲染窗口。
- 依赖 `capture/session.json` 之外的自有账号存储：`app/client/data/identity-v2.json`
  （含会话凭据，勿外发）。
- 目前未做赛事提醒/签到等能力，只覆盖"登录 → 浏览 → 订阅 → 自动报名"。
