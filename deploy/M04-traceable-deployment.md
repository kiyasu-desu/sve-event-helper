## 实现

- `deploy/release.py` 从明确 Git 提交对象构建固定运行白名单目录，生成 release.json，记录发布 ID、SHA、UTC 构建时间、schema 2/兼容 schema、逐文件精确 SHA-256 和按设计排除项。未提交内容不参与构建；缺少必需文件拒绝，不接受额外私有文件或符号链接。Linux 脚本/unit 统一 LF。
- 预检验证完整性、Python 3.10 语法、依赖、私有配置和当前身份数据。候选服务器导入使用临时假数据与合成签名配置，阻断网络、子进程和应用线程，不启动调度。预检可创建临时目录，默认只读检查则不创建。
- 停写切换取得数据目录独占锁，先保存受保护的一致私有快照与代码备份，再执行 prepared/copying/complete 事务。固定代码文件逐个刷盘替换，主目录无需转换为 Git 工作区；不是整个目录的一次原子替换。新服务拒绝在未完成事务上启动。
- 完成的同包重复升级为无改动成功；坏哈希、缺文件/依赖、异常配置、路径穿越/链接、代码与数据路径重叠、遗失权威数据或不兼容 schema 拒绝。代码切换不复制来源 settings/账号/日志，不清理目标数据，不安装依赖、不变更 unit。
- recover/rollback 校验旧代码哈希与当前 schema，恢复前一份完整公共代码，可从 rolling_back 中断继续。无论最新昵称、会话、订阅、记录或 pending 怎样变化，都不自动恢复旧私有数据快照。备份损坏或 schema 不兼容则保持暂停。首次安装无旧代码时回到无代码状态，不虚构可运行的旧版本。
- `/api/version`、`/api/health` 只返回启动时捕获的发布 ID、源码 SHA、构建时间、schema、启动时间、PID 和存储就绪状态。磁盘替换不会改变当前进程身份。无清单的开发/旧部署标为 legacy-unversioned。接口不证明调度线程推进，M06 仍独立。
- `verify.sh` 默认只读，移除旧上游会话检查、poll/watchdog 执行、临时 JSON 文件和字节码写入。校验清单、事务、依赖、私有配置/数据权限、目录可写性和 systemd 单一执行点；可显式核对 loopback 健康接口与磁盘发布一致。
- 单独的 `--validate-upstream --account-id` 只请求一次指定官方资料并校验 UID，不写会话或资料；`--test-notify` 明确发送测试消息，输出仅渠道接受状态。两项不会在默认检查或预检中执行；真实报名没有自检入口。
- install.sh 仅首次安装，upgrade.sh 仅停写切换，服务激活与手机生产验收单独执行。模板禁用字节码，不安装 retired poller unit，既有生产 unit/drop-in 不自动改写。原 HTTPS、Cloudflare Access、隧道和已安装 Android 入口保留。文档更正“通知一定送达”和旧 poller 常驻指引。

## 上线前补充修正：主页慢轮询与旧入口回退保护

修复基线为已合并 M04 的 `30f2864`，独立分支 `codex/m02-m04-predeployment-fixes`，本分支按用户要求一并处理两项上线阻塞，不部署生产。

主页原本只接受最后发起的请求，持续超过轮询间隔的成功响应会全部被丢弃。现在按已处理响应的序号过滤，尚未完成的新请求不会使旧响应失效；较新结果已经处理后，迟到的旧成功/失败仍被忽略，跨账号 epoch 的响应继续拒绝。连续慢请求、离线恢复、响应乱序和账号切换均有离线页面回归。Service Worker 壳版本提升为 sve-v9-predeployment，无需清 Cookie 或重新安装 APK。

原回退循环过早恢复旧 server.py，而 M01 没有 releaseinfo 事务检查。新增回归使用 Git 中实际 M01 入口，在恢复核心文件后注入故障，确认旧逻辑能进入调度恢复和 HTTP 启动替身，复现风险；修复后相同路径执行的是无依赖的临时拒绝入口，导入阶段即退出。

回退先用临时入口保护现有启动路径；其他文件恢复后逐项校验，事务提交 rolled_back，然后最后恢复旧入口。entry_pending 标记覆盖提交后到入口释放/元数据收尾的中断；恢复不会对该阶段误报无需操作，会重新校验公共代码再完成收尾。已完成且入口完整的回退重试仍幂等。应用数据 schema 保持 2；临时入口与标记仅属于代码部署事务，不修改账号、会话、订阅或历史。

新增故障注入还覆盖 rolling_back、其他文件恢复完毕、事务已提交但入口仍封锁、入口刚发布，以及恢复文件漂移拒绝。复核实际启动文件，而非仅调用 M04 的 snapshot 检查器。原数据 hash 保留断言继续执行；没有启动真实 HTTP 服务、调度、官方请求或通知，Linux systemd 和真机认证链路仍未验证。上线前应从合并此次修正后的最终 SHA 重新构建完整发布包，使用其中的新工具执行升级和回退。
