## 资料刷新行为

- 每个账号卡片提供“刷新资料”。登录原本就读取并验证官方资料，成功提交时现在同时记录最近成功时间，无需紧接着重复请求。
- 单独的后台线程轮转全部有效账号，不只刷新当前选择。`config/settings.json` 可设 `profile_refresh_interval_seconds`，默认 600 秒、最小 10 秒；配置不合法时回落默认值。旧 schema 2 缺少成功时间时默认 0，启动后进入待检测集合。
- 同一时刻最多一个资料请求；重复手动请求合并到同一任务。成功后手动操作有 5 秒间隔，失败按 30、60、120 秒递增退避，最多 1 小时。轮转包含网络耗时，周期到期表示可开始检测，不保证上游异常时的发现时限。
- 请求使用独立 Account 会话快照，网络等待不持有全局锁或报名所用 Account 的凭据锁。资料请求和自动报名的网络动作互不串行等待。
- 官方响应 UID 必须与目标 account_id 相同；非法 UID、无效资料或上游异常均保留原资料。公开状态只含错误类别，不含响应正文、手机号或会话。
- 发布结果前再次核对原账号对象、总版本和执行模式。重新登录、删除、删除后恢复会使旧结果失效，不能覆盖较新资料或复活账号。成功只写展示字段和资料/总版本，不写回快照中的 sessionid，不重建调度器，不改订阅或历史正文。
- 账号标题、批量结果标签、订阅分组、记录的当前账号标签及新通知都按 UID 解析当前名称。特殊字符按文本处理。同名账号仍显示 UID，勾选与操作绑定 ID。

后台由 `main()` 在身份载入和调度恢复后启动；导入模块或 GET 状态不会启动它。远端模式只由执行服务器刷新，本机转发明确操作并读取服务器摘要，不把离线缓存昵称同步回服务器。

## 协议、持久化与兼容

新增 `POST /api/account/profile/refresh`，请求必须含明确 `account_id` 与 `expected_version`，成功响应为 `ok/account_id/queued`。它只表示排队，资料是否成功以随后状态为准。版本冲突要求重新读取摘要，不自动强制重试。请求不接收昵称或会话写入字段。

`/api/state` 的账号行及 `/api/accounts/summary` 新增：

| 字段 | 含义 |
|---|---|
| profile_version | 成功资料更新计数，重新登录同样更新 |
| profile_updated_at | 最近成功验证资料的 Unix 秒时间，0 表示尚无记录 |
| profile_status | idle / queued / running / failed |
| profile_refreshing | 排队或执行中 |
| profile_error | identity_mismatch / upstream_error / invalid_response 或 null |
| profile_next_refresh_at | 下次可检测时间，0 表示待首次检测 |

仅 `profile_updated_at` 是新增持久化字段；任务状态、失败次数及退避保存在执行进程内，重启后重新安排，不宣称跨重启保持退避。原总版本、资料版本继续保存在同一个 schema 2 主文档，成功时间须为非负有限数值。无需迁移、复制账号表或重新登录全部账号。

页面正常每 2 秒读取执行端状态，资料成功提交后在下一次有效轮询显示新昵称；轮询不会请求官方资料。断网保留最近界面并明确标记过期，联网和恢复前台时立即读取服务端。晚到的旧状态响应不能覆盖新页面。订阅页更新分组标题时保留卡片及展开状态。Service Worker 版本为 `sve-v7-m02`，API 仍只走网络，不返回离线缓存冒充实时资料。

既有 Android `/api/login/cookie` 载荷、响应必需字段和 `sve://login` 不变，原 HTTPS/认证入口和私有构建配置不变。旧客户端无需使用新增刷新接口，也不能通过旧整表同步覆盖新资料。旧页面已有的版本前置条件仍可能因资料版本更新而拒绝操作，需要重新读取后明确操作。

## 发布与回退

生产发布另行授权：先重新核对实际版本、运行数据及报名窗口；保存受保护的一致快照；按 M00 的保留数据流程暂存并核验变更后的 server.py、core/sveapi.py、core/identity_store.py 和三个 UI 文件，确保只有一个执行点。私有 settings 无需覆盖，缺少新周期配置时采用默认值。启动后检查资料任务状态、地区和赛事、账号身份、订阅与记录，并通过现有手机认证入口完成回归。不能以真实报名或通知发送作为默认验收动作。

回退可使用本次核验的 M01 基线完整兼容代码（不要混用不同版本的 server/core/UI）。schema 仍为 2，M01 可忽略新增成功时间；保留当前 identity-v2.json 中最新账号、会话、订阅、记录和版本，不恢复上线前数据快照覆盖新变化。回退到 schema 1 或不含 M00 保护的旧版本不在此路径内。发生存储发布不确定时执行仍暂停，应核对磁盘最终主文档并重启，不用旧内存继续写入。
