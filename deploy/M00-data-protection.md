# M00：同步与升级的数据保护

本工作包最初基于 M07 提交 `7569c12ebf81a03cf3f9c4605af8f9d7035d37f9`，分支为 `codex/m00-data-protection`。M07 已通过 PR #1 合入 main；本分支现已合入该主分支提交 `a37be83`，包含后续敏感路径拦截与签名样本查询一致性修正。采用合并方式对齐，保留原 M00 提交历史，不强制推送。后续集成顺序为 M00 → M01。此次仅开发和隔离演练，没有访问服务器核对最新运行版本、修改线上文件、启停服务或生产部署。

## 行为与协议

| 路径/动作 | M00 行为 |
|---|---|
| `POST /api/accounts/sync` | 旧整表请求只读兼容：不新增、不覆写、不删除、不改 active、不清订阅、不启动调度或通知。先校验完整报文和 UID 冲突；有效空表/子集返回 `ok:true, readonly:true, pushed:[], removed:[], purged:0`。非法或冲突请求返回 `ok:false` 和错误代码。 |
| 启动、启用远端、恢复连接 | 恢复隧道并读取安全摘要，离线缓存不会重建服务器账号或覆盖会话。旧自动推送回调保留为无操作，避免晚到回调恢复破坏性行为。 |
| `POST /api/remote/push_accounts` | 兼容旧按钮地址，只读比较两端账号数量、差异和同名 UID 冲突；新版按钮名为“比较两端账号”。 |
| `GET /api/accounts/summary` | 新增只读摘要：名称、UID、昵称、会话前置指纹 `revision`，以及 `session_write:1` 能力标志。不包含 sessionid、Cookie、手机号或通知配置；禁用 API 缓存。 |
| `POST /api/accounts/session` | 明确提交单个账号及 `expected_revision`。新账号用 null；更新使用摘要中的指纹。服务器通过官方 info 重新校验 UID/昵称，写入前在锁内再次比较前置条件。冲突不自动强制重试。 |
| 手机 `/api/login/cookie` | 原 Cookie 请求与 `ok/name/uid/nickname` 成功响应保持兼容；先验证官方资料和本机前置快照，再保存。无需换地址、清登录状态或安装新 APK。 |
| 本机选择/删除 | 不再整表推送，也不改变服务器全局 active。本机删除缓存保留服务器账号；服务器账号要在服务器界面明确删除，保留已有历史记录。 |
| 会话更新/调度 | 更新原 Account 对象，既有调度器可使用新会话；不为同一订阅创建第二个线程。远端模式不恢复本机缓存订阅的调度器，也不做本机孤儿清理；本地仍有活动调度器时拒绝启用远端。 |
| 关闭远端执行 | 存在任何本机缓存订阅（包括缺失账号的订阅）时拒绝切换，返回 execution_handover_required，保留远端配置、隧道及全部数据。现有协议没有确认远端调度器已完全退出的交接机制，单次只读检查或断开隧道不足以证明安全；暂不自动取消远端订阅或清空本机缓存。无本机缓存时允许关闭连接，远端订阅继续独立运行；已在本机模式时重复关闭仍幂等补启动缺失调度器。 |

普通请求不能凭“清单中没有某账号”表达删除。旧客户端即使继续发送空表、子集或缓存，也无法取得写入能力；但旧界面可能仍将只读响应显示为“推送成功”，应检查 `readonly` 并升级电脑客户端。新版连接旧服务器时明确拒绝提交，不回退到旧整表协议。

电脑与手机的明确登录都拒绝无效 UID、同名异 UID 及同 UID 改名；已有数据原样保留，登录尝试不会覆盖旧账号。此次没有临时追加后缀冒充同名共存。M01 将实现完整 UID 身份和迁移，包括版本、删除墓碑及旧操作兼容。服务器会话接受后若本机缓存保存失败，应以服务器为准核对，不自动用缓存补推。

`revision` 是现有账号字段的 SHA-256 内容指纹，不含可还原的明文会话，也不是 M01 的持久递增版本或删除墓碑。没有改变 accounts/subscriptions/records 的存储 schema。网络结果不明时先刷新摘要再处理，不能把旧预期版本改成新版本后静默重放缓存会话。

浏览器登录窗口打开前、Cookie 兑换前，先记录本机版本、远端执行配置和远端账号版本摘要。登录完成后提交单个会话时固定使用这份远端前置版本，不读取新版本来重试覆盖；远端摘要不可用时不开始本次登录，执行配置变化时要求重新登录。

远端配置/隧道切换、登录摘要读取和会话提交通过独立互斥锁串行处理；连接占用时返回可重试错误。登录只接受配置匹配且进程运行中的隧道，提交前复核仍是同一个隧道对象。更换端口连接前等待旧 SSH 进程及维护线程退出，超时终止并等待；无法确认退出则不建立替代隧道。新隧道尚未运行时拒绝登录，避免把新配置与旧连接组合使用。

替换隧道失败会回滚内存和持久化远端配置；旧隧道若已退出，保持旧配置供核对和重连，不将切换失败冒充成功。远端订阅和取消也占用连接互斥锁，并要求两端名称对应同一 UID；本机身份缺失、远端身份冲突或摘要不支持 subscription_identity:1 时拒绝操作。请求携带 expected_uid，服务器在修改前再次校验；订阅还会在详情请求返回后重查，避免校验和实际操作之间账号被替换。旧手机的本地模式请求可继续省略该字段，远端新客户端不会向不支持身份前置条件的服务器降级写入。

启用远端时，活动调度器检查与远端模式登记在同一锁内完成。本机订阅在详情返回后、保存订阅及登记调度器前复查模式；若期间启用远端，返回 execution_mode_changed，不保存或启动本次本机订阅，也不自动转发，请刷新后重试。恢复既有订阅同样在调度器登记前复查；已登记但尚未启动线程的调度器也会阻止启用远端。

调度线程独立登记，取消、删除或自动移除订阅不移除此登记；直到调度函数返回或异常退出后才解除执行权拦截。设置 stop_flag 不代表已退出；仍在网络请求或复核阶段时继续拒绝启用远端。详情返回及报名提交前复查停止标志，避免取消后继续进入新报名；已在途请求必须等其返回后再切换执行点。

## 安装复制保护

安装器调用独立 `copy_runtime.py`，只复制服务器代码、UI、静态地区数据、配置示例、部署工具与 unit。测试代码、settings、会话、通知配置、抓包、日志和字节码缓存不从源目录导入。目标已有私人数据及备份不删除、不替换；原目录升级直接跳过复制。静态 areas.json 可随代码更新，首次安装也会取得它。

复制前对全部候选目标做路径和符号链接预检；代码文件采用临时文件替换。该步骤不是整个发布目录的原子切换，缺少依赖或复制中断仍可能留下部分新代码；完整暂存、清单校验、维护窗口和代码回滚属于 M04。安装器仍会安装系统依赖、调整目录所有者/权限和操作服务，**不能把整个 install.sh 当作只读检查或直接在生产重跑来验证保护**。

此前的目标数据清理分支与旧 poller 会话自动导入均已移除。首次安装需明确提供私人配置/登录，不能从打包来源的 settings 或旧 session 文件自动导入凭据。生产部署仍须先核对实际线上文件和唯一执行点，再按授权备份、停止写入和演练。

## 隔离验证与哈希报告

只运行新隔离用例，不直接运行旧的 test_auto_remove/test_completion_chain，也不运行真实客户端或安装器：

```powershell
& .\vendor\venv-client\Scripts\python.exe -B -m unittest discover -s tests -p 'test_m00*.py' -v
python -B -m unittest discover -s scripts/security -v
python -B -m unittest discover -s scripts/probe -p test_list_sign.py -v
```

用例在导入业务模块前设置临时 SVE_DATA_DIR、合成密钥并禁止网络、进程与真实线程。settings、notify、日志和持久化路径全部指向临时目录；生产数据/配置/相关日志的前后哈希另作不变断言。所有账号均为合成数据，官方 info、Cookie 换会话和通知均使用替身或禁止调用。

升级复制可用自建假来源和假目标目录单独演练，不需要 root、systemd 或联网。暂停假目标写入后生成两份哈希报告（输出文件放在被扫描目录之外，不能提交）：

```bash
python3 deploy/data_hashes.py /tmp/sve-m00-demo/target --output /tmp/sve-m00-before.json
python3 deploy/copy_runtime.py /tmp/sve-m00-demo/source /tmp/sve-m00-demo/target
python3 deploy/copy_runtime.py /tmp/sve-m00-demo/source /tmp/sve-m00-demo/target
python3 deploy/data_hashes.py /tmp/sve-m00-demo/target --output /tmp/sve-m00-after.json
cmp /tmp/sve-m00-before.json /tmp/sve-m00-after.json
```

来源假目录至少需含 server.py 和静态 areas.json；其他私人文件自行用假内容构造。`data_hashes.py` 扫描 config、capture 和运行 data 中的文件，排除静态地区数据/README 与配置模板；支持 `--data-dir` 指定外部假数据目录。不覆盖既有报告，POSIX 下创建即为 600。报告含文件名和哈希，仍须放在受保护位置。此方法可在未来获准生产维护时用于一致性备份核对，但本次未对生产运行这些命令。

## 验证结论与限制

- 对齐 main 后的本机回归结果：31 个 M00 用例中 30 个通过、1 个因真实符号链接创建权限跳过；M07 扫描器 7 个测试、签名样本查询一致性测试（含 5 组候选子场景）通过。M00 测试解释器为 Python 3.11，另做 Python 3.10 语法与内存编译检查。
- API 回归覆盖服务器 14 账号/本机 4 账号、旧空表/子集/重复/坏批次、同名异 UID、改名、UID 类型、单账号新增与重新登录、上游失败/身份不符、晚到更新、落盘失败、首次安装连续登录、两种登录入口及旧 Cookie 响应兼容。

- 已检查 Python 3.10 语法、Bash 语法、Linux 脚本 LF、UI JavaScript 语法及 PWA 缓存版本更新。未改变 APK、认证入口或官方报名边界。

## 发布、恢复与后续

发布时先上线服务端保护，再更新电脑客户端。此项没有 schema 迁移，也不要求清空账号或全部重新登录。回滚代码不会要求回滚数据；不要用旧快照覆盖升级后新增会话。旧服务端会恢复危险整表语义，不能在旧客户端可连接时直接退回旧同步代码；保留本保护或停止旧同步来源后，按专门回滚方案处理。

下一项建议 **M01：以 UID 统一账号身份**，在 M00 保护之上处理同名共存、改名迁移、未知身份拒绝、账号/订阅/历史引用、删除版本与离线冲突。共享 server.py 按 M07 → M00 → M01 顺序集成，避免分支并行覆盖。
