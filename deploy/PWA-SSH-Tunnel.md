# 手机接入：SSH 隧道 + PWA

> 适用场景：想在手机上操作赛事界面，**同时**手机上还开着别的 VPN。
>
> 为什么不用 Tailscale：Android 的 `VpnService` **全局只允许一个活跃实例**，
> Tailscale 与其它 VPN 互斥。SSH 隧道是普通 TCP，**不占 VpnService 槽位**，
> 所以两者可以共存。

---

## 一、原理

```
手机 SSH 客户端 ──SSH 出站──> 服务器:22
   └─ 本地端口转发  127.0.0.1:8901（手机） → 127.0.0.1:8901（服务器）
        └─ 手机浏览器访问 http://127.0.0.1:8901
```

三个关键性质：

| 性质 | 说明 |
|---|---|
| **不占 VPN 槽位** | SSH 是普通 TCP 连接，手机 VPN 照常运行 |
| **`127.0.0.1` 是安全上下文** | 所以 Service Worker 与「安装应用」都能用，PWA 功能完整 |
| **零公网暴露** | 不开放任何入站端口、不改 Azure NSG；认证由 SSH 承担 |

**服务器端无需任何改动**——代理本来就监听 `127.0.0.1:8901`。

---

## 二、准备：在手机上生成专用密钥（推荐）

**不要把电脑上现有的私钥复制到手机。** 手机更容易丢失，应该用一把**独立的、
权限受限的**密钥，丢了可以单独吊销。

### 1. 手机端生成密钥

用 **Termux**（F-Droid 安装，免费）：

```bash
pkg update && pkg install openssh
ssh-keygen -t ed25519 -C "phone" -f ~/.ssh/sve_phone
chmod 600 ~/.ssh/sve_phone
cat ~/.ssh/sve_phone.pub        # 复制这一行
```

### 2. 把公钥加到服务器（并限制它的能力）

在**服务器**上编辑 `~/.ssh/authorized_keys`，追加一行：

```
no-pty,no-agent-forwarding,no-X11-forwarding,no-user-rc,permitopen="127.0.0.1:8901" ssh-ed25519 AAAA...手机公钥... phone
```

这一行做了两件事：

- `permitopen="127.0.0.1:8901"` —— 这把钥匙**只能**转发到这一个目标，
  即使手机丢失，也无法用它访问服务器上的其它端口或服务
- `no-pty` 等 —— 不允许开交互式 shell、不允许 agent 转发

> 验证：用这把钥匙连上去执行 `ls` 应当被拒绝，但端口转发正常工作。

## 三、建立隧道

### Termux（推荐，免费且可控）

```bash
ssh -N -L 8901:127.0.0.1:8901 \
    -i ~/.ssh/sve_phone \
    -o ServerAliveInterval=30 \
    -o ExitOnForwardFailure=yes \
    <用户名>@<服务器地址>
```

参数说明：

| 参数 | 作用 |
|---|---|
| `-N` | 不执行远程命令，只做转发 |
| `-L 8901:127.0.0.1:8901` | 把手机的 8901 转到服务器的 8901 |
| `ServerAliveInterval=30` | 每 30 秒发心跳，防止中间设备掐断空闲连接 |
| `ExitOnForwardFailure=yes` | 转发建不起来就直接退出，**避免"以为连上了其实没通"** |

### 让它一键启动

在 Termux 里存成脚本 `~/.termux/tasker/sve-tunnel.sh`（或 `~/bin/sve-tunnel`）：

```bash
#!/data/data/com.termux/files/usr/bin/bash
termux-wake-lock          # 防止 Android 休眠杀掉进程
exec ssh -N -L 8901:127.0.0.1:8901 \
     -i ~/.ssh/sve_phone \
     -o ServerAliveInterval=30 \
     -o ExitOnForwardFailure=yes \
     <用户名>@<服务器地址>
```

配合 **Termux:Widget**（F-Droid）可以在手机桌面放一个图标，**点一下即建隧道**。

### 其它客户端

| 客户端 | 说明 |
|---|---|
| **ConnectBot** | 免费开源，`Port forwards` 菜单可加 `8901:127.0.0.1:8901` |
| **JuiceSSH** | 端口转发属**付费版**功能，用前先确认 |
| Termux + Termux:Widget | **推荐**：免费、可脚本化、可一键 |

## 四、安装 PWA

隧道建立后（保持 Termux 在前台或后台运行）：

1. 手机 Chrome 打开 **`http://127.0.0.1:8901/`**
2. 菜单（⋮）→「**安装应用**」或「添加到主屏幕」
3. 装好后有独立图标，打开即全屏、无地址栏

> ⚠️ **必须用 `http://127.0.0.1:8901`**，不要用服务器的公网 IP。
> 前者是安全上下文（localhost），后者不是——用后者**不会出现安装入口**，
> 也没有 Service Worker。

---

## 五、日常使用

```
要用时：打开 Termux → 点桌面图标建隧道 → 打开「SVE 赛事助手」
用完：  隧道可以留着（很省电），或关掉 Termux
```

**重要**：隧道只是"你操作界面"的通道。**服务器上的自动报名独立运行，
完全不需要手机、不需要隧道**——关掉手机一样会按时抢位并推送通知。

## 六、故障排查

| 现象 | 原因与处理 |
|---|---|
| 浏览器「无法连接」 | 隧道没建起来。看 Termux 里的报错；确认 `sve-agent` 在跑 |
| `bind: Address already in use` | 手机上 8901 被占。改用别的本地端口：`-L 18901:127.0.0.1:8901`，然后访问 `http://127.0.0.1:18901` |
| 用一会儿就断 | Android 省电策略杀了 Termux。给 Termux **关闭电池优化**，并用 `termux-wake-lock` |
| 界面打不开但隧道正常 | 确认服务器上 `systemctl is-active sve-agent`，以及它监听的是 `127.0.0.1:8901` |
| PWA 装上后打不开 | 正常：图标在，但**隧道没开时连不上**。先建隧道再打开 |
| 界面显示报错而非数据 | 隧道断了。Service Worker 对 `/api/*` **一律不缓存**（刻意如此），所以不会拿旧数据糊弄你 |

## 七、安全说明

| 项 | 说明 |
|---|---|
| **私钥不要跨设备复制** | 手机用**独立密钥**，丢了在服务器上删掉那一行 `authorized_keys` 即可吊销 |
| **限制转发目标** | `permitopen="127.0.0.1:8901"` 让这把钥匙只能到这一个端口 |
| **本地端口只绑本机** | `ssh -L` 默认只绑手机的 `127.0.0.1`，同一 Wi-Fi 下别的设备访问不到 |
| **不暴露公网** | 全程不需要开放入站端口、不需要改 NSG、不需要域名 |
| **界面本身没有认证** | 所以**绝不能**把 8901 直接暴露到公网。本方案正是为此设计：认证交给 SSH |

---

## 八、什么时候该换方案

如果"手动建隧道"让你觉得麻烦，可以升级到 **Cloudflare Tunnel + Access**：

- 手机浏览器直接访问 `https://sve.<你的域名>`，无需隧道、与 VPN 共存
- Access 提供认证（邮箱验证码等），同样不需要开放入站端口
- **PWA 那部分成果完全复用**，只是接入方式变了

代价：需要一个托管在 Cloudflare 的域名（年费约 ¥30~70）。
