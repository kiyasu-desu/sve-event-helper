# M01：UID 账号身份统一

开发起点：已合并 M00 及评审修正的 main `6994f2d2cb21d36f9008cb2fbfbaf18fcfc66ce8`。分支：`codex/m01-account-identity`。M00 的隧道所有权锁、登录前版本快照、取消订阅身份校验、旧执行线程退出前禁止交接等保护继续保留。

本次交付为代码与隔离演练，没有连接生产服务器核验最新运行版本，没有应用真实数据迁移、启停服务、真实报名或发送通知。GitHub 合并状态不能代替服务器部署基线。未来发布须先核对实际线上文件、运行环境、数据目录和唯一执行点。

## 身份与存储

官方 UID 的规范十进制字符串为 `account_id`。拒绝缺失、布尔、浮点、负数、零及非十进制值；整数与字符串、前导零表示会收敛到同一个 ID。没有依据未公开的上游约定额外猜测 UID 上限，传给上游的 uid 使用经过校验的官方资料字段类型。

账号表、默认 active_account_id、订阅、历史、调度器、批量选择和 HTTP 转发均使用 ID；名称仅展示。同名不同 UID 独立存在；同 UID 改名并重新登录更新原对象，保留其订阅、历史及勾选 ID。界面同时显示 UID。昵称含引号、HTML 字符和分隔符不会进入事件处理器的身份参数。

权威数据为 `<SVE_DATA_DIR>/identity-v2.json`，默认仍在 `app/client/data/`。它包含整个身份数据集：

```jsonc
// 仅说明结构；以下 ID、昵称均为合成示例。
{
  "schema_version": 2,
  "generation": 0,
  "active_account_id": "10001",
  "accounts": {
    "10001": {
      "account_id": "10001", "uid": 10001, "nickname": "test-shared",
      "name": "test-shared", "sessionid": "<private session>",
      "deviceid": "<private device>", "user_agent": "okhttp/4.9.2",
      "version": 1, "session_version": 1, "profile_version": 1,
      "legacy_names": ["test-old"]
    }
  },
  "subscriptions": {}, "records": {}, "pending": [],
  "tombstones": {}, "operations": {}
}
```

账号、订阅和记录不再分三个文件分别切换。每次写入发布一个完整文档，先校验身份及数据集代数，临时文件刷盘后原子替换；POSIX 下再同步目录。文件创建即使用私有权限，Windows 仍须使用受保护目录/ACL，不能把 POSIX 模式位当成完整的 Windows 权限审计。

服务整个生命周期持有目录写入锁，进程内注册和持久化继续受 LOCK 保护。读取脚本可以只读新数据集，不能绕过服务写会话；旧 poller/自动报名/直连 action 入口拒绝在 v2 目录上成为第二执行点。若替换已发生但目录持久化确认失败，停止后续写入与调度，检查存储后重启读取最终文档，不在旧内存上继续执行。

普通文件提交失败或发现外部代数变化时同样暂停执行，避免未落盘的内存变更参与报名。迁移保留的会话首次使用前会查询官方 UID；身份不符则不发送报名/取消请求，暂停相关任务并把原账号/订阅保留到 pending。晚到的旧版本身份错误不能禁用已重新验证的新会话。已明确登录验证的会话缓存此校验结果，正常轮询不会每次重复查询资料。身份不符而暂停的订阅需要核对后明确重新订阅，不因重新登录而盲目恢复。

## HTTP 与混合客户端

| 操作 | 当前契约 |
|---|---|
| 只读摘要 | `/api/accounts/summary` 返回 `schema_version:2`、`session_write:2`、`subscription_identity:2`，以及 ID、昵称、版本、旧名称映射和删除摘要。不包含会话、Cookie、手机号、通知密钥。 |
| 会话新增/更新 | `/api/accounts/session` 请求含 account（明确 account_id）、expected_version、operation_id。服务端重新读取官方资料并匹配 UID，锁内再次比较版本，再写入。客户端输入的版本不能成为服务端版本。 |
| 资料与会话版本 | version 是总版本；session_version/profile_version 分别保留会话、资料变更计数。重新登录更新两者；后续 M02 的纯资料更新不得覆盖会话。M01 不提供后台昵称轮询。 |
| 幂等重试 | 同 operation_id 和同会话载荷返回原凭据，不重复建号或重启任务。会话重试即使重新读到了较新前置版本，也只能重放原结果，不能覆盖新会话。同标识换载荷拒绝。删除重试不会重复清订阅或通知。 |
| 删除 | `/api/account/forget` 要求明确 ID、expected_version、operation_id。停止对应订阅，保留历史和删除版本、昵称/旧名称。已开始的上游请求无法撤回，但旧 Account 被退役后不能启动新的请求。 |
| 删除后恢复 | UI 的“已删除账号 → 重新登录恢复”先确认 UID 与删除版本，再取得新会话；官方 UID 必须匹配。恢复账号不会恢复旧订阅。普通离线缓存、旧会话请求不能复活已删除账号。 |
| 当前选择 | 新页面请求携带 account_id；每个浏览器的选择使用独立 Cookie，不再让另一个客户端的选择改变当前请求身份。持久化 active_account_id 仅作默认展示/只读脚本默认项，不能为显式未知 ID 兜底。 |
| 旧名称操作 | `account`/`name` 同时检查规范 UID 与当前/历史名称候选，仅在候选为同一身份且预期 UID 一致时兼容。UID 与另一账号名称冲突时拒绝，不优先选任一解释；改用明确 `account_id`。未知或歧义参数拒绝；参数指向已删除 UID 或其旧名称时必须明确 UID，不能转给现在的同名账号。 |
| 旧整表同步 | `/api/accounts/sync` 继续只读兼容，空表、子集、重复及坏批次都没有覆盖/删除能力。M00 电脑客户端因能力版本不同而拒绝新会话提交，需要更新电脑代码，不回退不安全协议。 |
| 手机 Cookie 登录 | `/api/login/cookie` 继续接受原 cookies 字符串/字典和 udid；成功响应保留 ok/name/uid/nickname，新增 account_id。已安装 APK 仍按 nickname/name 显示结果，原 `sve://login` 通道不变。 |

新网页在打开官方登录页前调用 `/api/login/intent`，固定本机/远端版本，并以本域 HttpOnly Cookie 将同一登录操作关联到 Cookie 回调。这样同一次回调可重试，新发起登录仍能刷新同 UID 的昵称。Cookie 回调结束即清除此单次意图 Cookie，避免影响之后从已安装 APK 原生按钮发起的新登录；不清 Access/官方登录 Cookie。意图 30 分钟过期，服务重启期间未完成的登录须重新从界面发起，不影响已保存账号会话。

旧 APK 直接使用原生按钮且不带登录意图时仍可完成明确登录；账号 ID 和服务端前置版本保护仍生效。旧载荷没有幂等键时不承诺每次 HTTP 重发返回同一版本号，但不会创建第二个同 UID 账号或重复注册调度器。新协议的 operation_id 重试使用持久化凭据。

远端模式以服务器摘要为成员集合和版本来源，服务器独有账号也可在电脑界面选择。赛事查询、直接/批量报名、取消和记录操作转发到执行服务器，不要求本机缓存含该账号会话。启动/重连只读，不重建服务器账号。普通同步与远端会话导入不修改服务器全局默认选择。原 HTTPS 地址、Cloudflare Access、隧道与 Android 构建地址均未修改。

调度器持有的账号对象在受控锁内更新会话；取消中的旧线程退出前不允许为相同 ID/赛事注册新线程。完成后的延迟移除绑定原订阅实例，不能删除后来创建的同键订阅。暂停或身份待处理数据不启动守护。

## 离线迁移：默认只读预览

迁移工具不登录、不查询上游、不发通知。服务器、本机数据各自预览和迁移，不复制某端整表覆盖另一端。以下是**自建假目录**的演练命令，不是本次已对生产执行的操作：

```bash
python3 scripts/identity_migrate.py /tmp/sve-m01-demo/data
python3 scripts/identity_migrate.py /tmp/sve-m01-demo/data --action apply --writers-stopped
```

`--writers-stopped` 表示操作者已完成停写检查，不是对旧进程存活状态的自动证明。实际维护时须在维护窗口暂停服务、旧 poller、可能重启它们的看护/控制器和本地写入来源，先取得一致性备份。M01 的目录锁能阻止新的 v2 执行者，但旧版本没有此锁，不能只靠锁或此参数推断旧版本已停止。

预览校验旧 accounts.json、active、subscriptions.json、records.json，stdout 只输出数量与问题类别，不输出真实 UID、昵称、会话或服务器地址。迁移按以下规则处理：

- 有效 UID 按规范 ID 归并；相同 UID 的会话/设备/资料一致时确定性合并旧名称。若无法判断哪个会话/资料更新，不按文件顺序挑选，全部保留为待处理。
- 订阅/记录有 UID 时优先使用，同时验证旧名称对应账号 UID。两者冲突、UID 非法或身份未确认的项保留在 pending，不启动报名，也不通过孤儿清理删除。
- 不同 UID 的同昵称账号分别保留；同 ID/赛事的重复订阅合并日志和来源，任一来源暂停则保持暂停，并保留重复原件供核对。
- 原账号缺失但记录带有有效 UID 的历史可保留为已删除身份；对应订阅仍待处理，不能凭历史重建会话。曾被同名覆盖且没有备份的账号无法凭昵称恢复，须重新登录。

应用流程：在私有 `identity-backups/<随机事务目录>/` 保存三个旧文件的逐字节快照、哈希和完整迁移候选；写入事务状态；将旧文件换成拒绝旧读取器的 schema 标记；最后发布单个 v2 文档并标记 complete。原地区数据、notify、remote 和 settings 不参与替换。地区资源继续保留，外部数据目录缺少地区文件时读取代码目录的静态资源。

pending、备份与迁移候选含凭据，不能贴入聊天、PR 或发布包。详细旧名称→UID 映射与冲突原件位于受保护候选/快照中，公开预览只有计数。待处理项须人工核对身份与会话后单独处理；不能直接把 pending 重新塞入调度集合，也不能用追加昵称后缀假装完成身份迁移。

## 中断恢复与回退

```bash
python3 scripts/identity_migrate.py /tmp/sve-m01-demo/data --action recover --writers-stopped
python3 scripts/identity_migrate.py /tmp/sve-m01-demo/data --action rollback --writers-stopped
```

- prepared/fencing/激活后未完成等阶段中断时，新服务拒绝启动调度。recover 校验候选与旧输入后继续；发现新的旧格式写入则拒绝覆盖，先核对最新数据。
- 回退本身也有 rolling_back 事务状态，可继续完成；在没有任何 v2 业务写入时恢复旧文件的精确原始字节。备份不自动删除。
- 只要启用后数据有变化，自动向旧 schema 回退就会拒绝，不能用初始快照覆盖新会话、订阅或记录。已完成迁移的主文档缺失也不能通过初始候选默默重建。应保留/恢复最新 v2 数据，使用兼容 v2 的代码恢复服务，或单独制定人工核对方案。
- 旧代码无法理解 v2：旧文件标记使旧服务/旧写入器在读取阶段失败，而不是继续运行另一套权威数据。新版脚本只读 v2，禁止把新凭据写回旧文件。部署旧代码前必须完成合法回退；不能为了使旧代码启动而删除标记、改名主文档或重新导入本机缓存。

此方案不把多个独立文件的 replace 当作整体原子；激活前依靠持久化事务状态、私有快照和停写，激活后账号/订阅/记录共同使用单文档提交。它没有替代 M04 的完整发布暂存、清单与依赖校验，也没有把整个 install.sh/verify.sh 变成只读工具。
